# Design — ar-getting-paid

## Context

Invoices today are ledger-first: an invoice row plus AR postings, with
mark-paid/void actions. This change adds the client-facing and
statutory layer on top without touching the posting invariant.

## Goals / Non-Goals

**Goals:**
- Quotes → invoices with zero re-typing.
- Clients can view/pay instructions without an account.
- Exports a German/Belgian accountant can file (Factur-X, UBL).

**Non-Goals:**
- Online payment capture (Stripe checkout) — needs PCI/keys decisions;
  share links show instructions + reference QR instead.
- PEPPOL transport/network membership — data model is ready; transport
  is a separate change.
- Client portal accounts (login for customers).

## Decisions

- **Estimates reuse `invoice_lines` via a `doc_kind` discriminator**
  rather than a parallel table. WHY: one line model, one tax logic.
  Alternative considered: separate estimates tables — rejected
  (duplicated totals code).
- **Share tokens are random 256-bit, stored hashed** like API tokens.
  WHY: link URLs leak (email, logs); hash-at-rest makes DB theft
  insufficient to enumerate live links.
- **PDF/A-3 embedding via `lopdf` + prebuilt XMP template.**
  Alternative considered: headless-Chromium printing — rejected
  (binary bloat, sandboxing); wkhtmltopdf — rejected (unmaintained).
  The existing printable HTML remains the human copy; Factur-X wraps it.
- **CII XML generated by hand-rolled serializer against the EN 16931
  subset.** Alternative considered: full CII crate — none mature in
  Rust at time of writing; the subset is ~40 elements and XSD-tested.

## Risks / Trade-offs

- PDF/A conformance claims need validation → Mitigation: CI runs
  `veraPDF` smoke check when available; test asserts embedded XML +
  metadata keys regardless.
- Recurring invoices surprising users → Mitigation: template page shows
  next run + last 3 issued; scheduler marks first-run as preview-only
  unless confirmed.
- Share-link scraping → Mitigation: noindex, rate-limited route,
  token revocation, no financial account data on the page.

## Migration Plan

1. Estimates migration + handlers (no behavior change to invoices).
2. Share-link table + routes.
3. Scheduler job kinds for recurring issuance + reminders.
4. E-invoice serializers + PDF embedding behind feature flag until
   validated.
